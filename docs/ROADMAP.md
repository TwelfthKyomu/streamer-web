## Игровые серверы (Minecraft и далее)

Планируется отдельным модулем `src/modules/gameservers/`. Портал должен уметь
показывать статус, привязывать аккаунты и выдавать привилегии за баллы.

### Как это работает технически

Плагин к серверу для базовых вещей не нужен — хватает штатных протоколов:

- **Server List Ping** (порт 25565) — онлайн/офлайн, число игроков, MOTD,
  версия. Работает всегда, ничего включать не надо. Этого достаточно для
  виджета «сервер онлайн, 12/60» на главной.
- **RCON** (порт 25575) — выполнение команд: `whitelist add`, `kick`, `ban`,
  `say`, выдача прав через LuckPerms. Включается в `server.properties`.
  Библиотека: `rcon-client`.
- **Query** (`enable-query=true`) — расширенный список ников онлайн.
- **Управление процессом** (старт/стоп/рестарт) — уже не протокол игры.
  Варианты: панель Pterodactyl с REST API (если серверов будет несколько),
  либо systemd + свой агент, либо Docker API.

### Привязка игрового аккаунта

1. Пользователь вводит ник на сайте.
2. Сайт генерирует одноразовый код и пишет его в `game_accounts`.
3. Игрок заходит на сервер и вводит код (командой плагина либо в чат,
   который читает бот).
4. После подтверждения сайт через RCON добавляет игрока в whitelist.

Без этого шага любой мог бы «привязать» чужой ник и получить чужие привилегии.

### Что это даёт зрителям

- [ ] Автовайтлист за подписку Twitch или порог баллов
- [ ] Покупка привилегий за баллы: `lp user <ник> parent add vip` через RCON
- [ ] Голосование за карту или режим следующего вайпа
- [ ] Игровая статистика в профиле на сайте
- [ ] Очередь на приватный сервер со стримером (сходится с механикой
      «очередь на игру» из v3)
- [ ] Начисление баллов за время на сервере

### Схема данных (добавить, когда дойдёт до реализации)

```
game_servers    id, kind, name, host, rcon_port, rcon_password_enc,
                query_port, panel_id, enabled
game_accounts   user_id, server_kind, game_uuid, game_nick,
                verified_at, verification_code
server_perks    id, server_id, code, title, cost, rcon_template
perk_grants     id, user_id, perk_id, granted_at, expires_at, transaction_id
```

### Требования безопасности

Это не пожелания, а условия, без которых сервер уведут.

- **RCON-порт не открывать в интернет.** Только с хоста сайта, через firewall
  или приватную сеть. RCON — протокол без шифрования, пароль ходит открытым
  текстом.
- **Пароль RCON шифровать в БД**, не хранить в открытом виде.
- **Команды строить из шаблонов с экранированием ника.** Ник приходит от
  пользователя; без экранирования через него инъектируется произвольная
  RCON-команда — это полный захват сервера.
- **Выдачу привилегий логировать** в `moderation_actions` и связывать с
  транзакцией баллов, чтобы спорные случаи разбирались по журналу.
- **Списание баллов и выдачу привилегии** связывать идемпотентным ключом:
  иначе при обрыве связи игрок платит, но ничего не получает.

## Юридические ограничения

Не рекомендации, а рамки, за которые нельзя выходить.

**Лутбоксы.** Кейсы открываются только за баллы, заработанные активностью.
Продажа баллов за деньги превращает механику в платный лутбокс, а аудитория
стримеров часто несовершеннолетняя. Донат может давать косметику, бейдж и
приоритет в очереди — но не ключи от кейсов.

**152-ФЗ.** База с персональными данными физически размещается на серверах в РФ.

**Модерация.** Премодерация обязательна с первого дня: за загруженный
пользователем контент отвечает владелец площадки.

**Авторские права.** Реквесты музыки и загрузка чужих видео — зона риска
при монетизации. Решать до запуска соответствующих разделов, не после.
